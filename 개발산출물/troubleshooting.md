## 1. pykrx 시총·펀더멘털·지수 빈 결과

### 발생 일시·담당자·영향 범위
- **발생 일시**: 확인 필요 — 1단계 smoke test 중 발견. 해결이 담긴 첫 커밋은 `a57b684`(2026-10-06 23:06, 초기 구현), 재실행 결과 기록은 `bedec97`(2026-10-07 10:36, `개발산출물/smoke_test_result.md`)
- **담당자**: Hunseokc (커밋 작성자)
- **영향 범위**: 국내 밸류에이션(시총·PER·PBR·EPS·BPS) 전 종목, 국내 지수(KOSPI·KOSDAQ). 일봉·종목명은 정상이라 "부분적으로만 실패"해 발견이 늦어질 수 있는 유형

### 문제 상황
- **기능**: 국내 밸류에이션 적재(`valuation`), 지수 적재(`indices`)
- **영향**: 시총·PER/PBR이 비어 매력도의 가치 팩터와 원화 환산 시총 순위를 계산할 수 없음
- **오류 메시지**: 시총·펀더멘털은 예외 없이 빈 DataFrame, 지수는 `KeyError: '지수명'` (ASSUMPTIONS A-01)

### 원인 분석
- **직접 원인**: pykrx 1.2.x는 KRX 정보데이터시스템의 시총·펀더멘털·지수 화면에 **회원 로그인**이 필요하다. 로그인하지 않으면 해당 엔드포인트가 빈 응답을 준다.
- **근본 원인**: pykrx는 **import 시점**에 `os.environ`의 `KRX_ID`/`KRX_PW`를 읽는다. `.env`에 값을 넣어도 pydantic-settings가 읽을 뿐 환경변수로 내보내지 않으면 pykrx는 로그인하지 못한다(A-04). 또한 비공식 라이브러리라 사이트 정책 변화가 그대로 영향을 준다.
- **확인 방법**: `python -m app.ingest.smoke`로 로그인 없음/있음 두 경우의 실제 응답을 비교(`개발산출물/smoke_test_result.md`), pykrx 소스 `website/comm/auth.py`에서 환경변수 읽는 시점 확인

### 해결 과정
1. smoke test로 로그인 여부에 따른 응답 차이를 실측해 원인을 로그인으로 좁힘
2. `export_krx_credentials()`(`backend/app/core/config.py`)로 `.env` 값을 **pykrx import 전에** 환경변수로 내보내도록 함
3. 로그인 세션 만료(1시간)는 pykrx가 자동 재로그인함을 소스로 확인(A-05)
4. 장애 대비: `PRICE_SOURCE_KR=yfinance`로 국내 소스를 바꿀 수 있게 하고(A-03), pykrx 실패 시 DART FY 기반 파생 밸류에이션(`DERIVED`)으로 대체(A-02)

### 해결 결과
- **정상화**: 로그인 후 일봉·시총·펀더멘털·지수가 모두 동작(2026-10-08 깨끗한 DB 재현에서 적재 실패 0건)
- **재발 확인 방법**: `python -m app.ingest.smoke` 재실행, `GET /api/v1/statistics/data-quality`에서 VALUATION·INDICES의 `last_failure_reason`, `python -m app.ingest status`의 최근 실패

### 재발 방지
- **코드**: `export_krx_credentials()` 호출을 pykrx import 경로 앞에 고정, 소스 전환(`PRICE_SOURCE_KR`)·DERIVED 폴백 유지
- **점검 항목**: README 환경변수 표에 `KRX_ID`·`KRX_PW`를 pykrx 사용 시 **필수**로 표시, 장애 시 점검 순서에 "KRX 로그인" 포함(README 운영 가이드)
- **문서**: ASSUMPTIONS A-01~A-05, `개발산출물/03` 1절, `개발산출물/smoke_test_result.md`

## 2. Cloud Run 인스턴스 교체 후 KRX 로그인 실패

### 발생 일시·담당자·영향 범위
- **발생 일시**: 2026-10-20 08:01 KST 첫 실패 ~ 09:35 KST 재배포로 복구 (Cloud Logging 기준)
- **담당자**: Hunseokc — 진단 로그 `82a59e3`(#95), KIS 교체 경로 `0a5067e`(#96)·`d3ba050`(#97)·섹터 지수 매핑(#98)
- **영향 범위**: KRX를 쓰는 국내 작업 전부 — 지수(KOSPI·KOSDAQ·KOSPI200), 노출 종목 일봉·밸류에이션, 백그라운드 재무 우선순위(거래대금). 해외 지수·환율·미국 종목, 화면 API는 정상(HTTP 5xx 0건)이라 화면만 보면 장애가 드러나지 않는 유형

### 문제 상황
- **기능**: 앱 안 스케줄러의 백그라운드 재무(08:00)·시세 갱신(4시간 TTL)
- **영향**: 국내 지수·시세가 전일 값에서 멈춤. 실패 기록이 남아 30분·60분 간격으로 재시도했지만 계속 실패
- **오류 메시지**: `JSONDecodeError: Expecting value: line 13 column 1 (char 25)` (`ingestion_logs`의 INDICES·PRICES·BENCHMARK FAILED)
- **같은 밤의 다른 ERROR(영향 없음)**: 01:05·05:05 KST 장 시작 전 "오늘" 지수 요청에 KRX가 빈 표를 돌려줘 pykrx 내부 `KeyError` + pykrx 자체 로깅 버그(`logging.info(args, kwargs)`) 트레이스백. 작업 결과는 `SUCCESS rows=0`

### 원인 분석
- **직접 원인**: pykrx는 **import 시점**에 KRX에 로그인한다(`website/comm/webio.py` 모듈 로드 → `login_krx`). 로그인 응답이 JSON이 아니면 `resp.json()`에서 예외가 나 import 자체가 실패하고, 이후 호출마다 import(=로그인)를 다시 시도해 같은 오류를 반복한다.
- **경과**: 07:21 Cloud Run이 인스턴스를 교체(플랫폼 정기 교체) → 08:01 새 인스턴스가 처음 pykrx를 불러올 때 로그인 실패(`KRX 로그인 시도...` 뒤 `완료` 없음). 09:35 재배포로 다시 교체된 인스턴스에서는 즉시 로그인 성공.
- **근본 원인**: **확정하지 못함.** 같은 계정으로 로컬에서 같은 로그인 절차를 실행하면 정상(`CD001`)이라 계정 문제는 아니다. 인스턴스(나가는 IP)에 따라 갈렸다는 점에서 KRX의 IP 단위 차단이 유력하지만, KRX 일시 오류일 가능성도 남는다. 당시 응답 본문을 남기지 않아 구분할 수 없었다.
- **pykrx 세션 관리의 한계**(소스 확인, 1.2.9): 만료를 서버 응답이 아니라 자체 1시간 타이머로만 판단한다 → 서버 쪽에서 세션이 끊겨도(중복 로그인 등) 최대 1시간 동안 끊긴 쿠키로 요청한다.
- **확인 방법**: `gcloud logging read`로 08:01 전후 로그, pykrx 1.2.9 휠의 `website/comm/auth.py`·`webio.py`, 로컬 로그인 재현 스크립트

### 해결 과정
1. 로그로 실패 범위(국내 KRX 작업만)와 시작 시점(인스턴스 교체 직후)을 좁힘
2. **진단 로그 추가**(#95): pykrx import(로그인) 실패 시 나가는 IP와 같은 로그인 절차의 응답(상태·형식·리다이렉트·본문 500자)을 10분에 1회 ERROR로 기록 → 다음 실패 때 IP 차단/KRX 점검/계정 문제를 구분
   - 첫 CI에서 버그 발견: `time.monotonic()`은 부팅 후 경과 시간이라 부팅 10분 안에는 첫 진단이 건너뛰어짐 → "아직 진단 안 함(None)"으로 구분
3. 재배포로 인스턴스를 교체해 복구(09:35 로그인 성공, 09:48 KOSPI·KOSPI200·삼성전자 SUCCESS)
4. **원인 미확정 상태로 시연할 위험**을 줄이려 공식 API 교체 경로를 준비 — 고정 IP(Cloud NAT)는 비용 때문에 제외
   - `PRICE_SOURCE_KR=kis`(#96): 한국투자증권 Open API로 일봉·지수·밸류에이션. KIS는 날짜별 전 종목 조회가 없어 대량 조회·상장 목록 provider를 두지 않고, 이미 검증된 "종목별 수집" 경로(yfinance 모드와 같음)를 타게 함
   - 일봉 1회 100행 제한 → 끝 날짜를 당겨 이어 받기 / 밸류에이션 = 현재 EPS·BPS·상장주식수 × 각 거래일 종가 / 배당(dps)은 KIS가 주지 않아 마지막으로 알려진 값을 이어 씀
   - 접근 토큰 24시간 재사용(메모리 + `/srv/data` 파일), 만료 응답(EGW00121·00123)이면 재발급, 발급 1분 제한(EGW00133)이면 61초 대기
   - migration `010_kis_source`(밸류에이션 source에 'KIS'), Secret Manager `KIS_API_KEY`·`KIS_API_SECRET`를 Cloud Run에 연결
5. **호출 한도 맞추기**(#97): 공지 기준 실전 초당 18건(신규 3일 초당 3건), 모의 초당 1건, 모두 계좌(앱키) 단위. 앱키가 모의투자로 발급되었으나 실전 서버에서도 시세 조회가 되는 것을 확인 → 실전 서버 시세를 쓰되 **가장 낮은 모의 기준(1.05초 간격)** 으로 호출
6. **섹터 히트맵 누락 발견·보완**(#98): 국내 섹터 등락률이 코스피 200 섹터 지수(KRX 1150~1160)를 `kr_index`로 받는데 KIS 매핑에 없어 KIS 모드에서 비게 됨 → KIS 업종 마스터(`idxcode.mst`)에서 대응 코드(2009~2018·2039)를 찾아 매핑

### 해결 결과
- **정상화**: 재배포 후 KRX 로그인·국내 적재 정상. KIS 경로는 실제 키로 임시 DB에 일봉 2년(100행씩 5회)·지수 3종·섹터 지수·밸류에이션 적재 성공, 삼성전자 PER = 종가 ÷ EPS 검산 일치, 전체 pytest 통과
- **KIS 모드 부하**(모의 기준 초당 1건, 운영 DB 국내 노출 16·비교군 54종목): 4시간 갱신 약 50건(1분), 일일 비교군 약 210건(4분), 처음 여는 종목 상세 약 11건(12초)
- **KIS 모드에서 멈추는 것**(시연 영향 없음): 상장 목록 갱신(신규 상장만 검색에 안 잡힘), 국내 업종 분류 갱신(기존 값 유지), 백그라운드 재무 우선순위(종목 번호 순)
- **계좌 안전성**: 앱이 KIS에 보내는 요청은 토큰 발급과 `quotations`(시세 조회) 3종뿐이다. 주문 주소·계좌번호(`CANO`)·해시키가 코드와 설정 어디에도 없어 거래가 일어날 경로가 없다.

### 재발 방지
- **운영 절차**: KRX 오류가 다시 나면 아래 한 줄로 전환(재배포 1~2분), 되돌릴 때는 `=pykrx`
  ```
  gcloud run services update stockmind --region asia-northeast3 --project stockmind-512107 --update-env-vars PRICE_SOURCE_KR=kis
  ```
- **원인 확정**: 다음 실패 때 `KRX 로그인 진단: egress_ip=... body=...` 로그로 판별 → IP 차단으로 확인되면 국내 소스를 KIS로 상시 전환
- **주의**: KIS 호출 한도는 계좌(앱키) 단위 — 운영 중에는 같은 키로 로컬에서 KIS를 호출하지 않는다
- **후속 과제**: 상장 목록·업종 분류를 KIS 종목 마스터 파일(인증·호출 한도 없음)로 받기, 배당(dps) 소스
