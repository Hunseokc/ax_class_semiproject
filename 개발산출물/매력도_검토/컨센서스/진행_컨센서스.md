# 진행: 컨센서스·애널리스트 의견 수집 (검토 → 구현)

> 새 세션은 **이 파일 하나**를 읽고, 아래 "다음 세션 시작 지시"의 step을 실행한다.
> 한 세션 = 한 step. step을 끝내면 결과 파일을 남기고, 이 파일의 단계 표·결과 칸을 고치고 커밋·push한 뒤 세션을 끝낸다(대화는 지워도 된다).

- 근거 문서

## 2. step 방식 규칙

- 각 step은 **입력 파일 → 할 일 → 결과 파일 → 완료 기준**으로 정의한다. 다음 step은 이 파일 + 표의 "입력"에 적힌 결과 파일만 읽으면 된다. 대화 기록에 기대지 않는다.
- 결과 파일에는 다음 step에 필요한 사실을 **모두** 적는다. 수치, 필드명, 단위, 매핑표, 미확인 사유가 들어가고, "앞 세션에서 봤듯이" 같은 표현은 쓰지 않는다.
- 원본 응답이 필요한 step(R3→R4→R5)은 `개발산출물/매력도_검토/컨센서스/raw/`를 읽는다. **이 세 step은 같은 PC에서 한다.** 다른 PC로 옮기면 R3부터 다시 받는다.
- 호출 스크립트 실행: 앱 이미지의 의존성·환경변수를 쓰도록
  `docker compose run --rm -e PYTHONPATH=/srv -v C:/seokhunchoi_Ax_Fullstack/stockmind/ax_stockmind/개발산출물/매력도_검토/컨센서스:/work api python /work/scripts/<스크립트>.py`
  (앱 모듈은 import만 하고 고치지 않는다. `app.*` import에는 `-e PYTHONPATH=/srv`가 필요하다. 키·토큰은 출력하지 않는다)
- 단계 1(R0~R7, G)은 프로젝트 코드를 고치지 않는다. 커밋은 `개발산출물/매력도_검토/컨센서스/`(raw·scripts 제외)와 `docs/review/**`(최종 보고서)만 한다.
- step이 계획보다 길어지면 멈추고, 알아낸 것을 결과 파일과 "겪은 문제"에 적은 뒤 같은 step을 새 세션에서 이어 간다.
- **step 종료 시 마지막 답변 끝에** 다음 세션 시작 멘트(복사해 붙일 코드 블록)와 **권장 effort**(단계 표 effort 칸 기준, 이번 step 결과로 바꿀 이유가 있으면 바꾸고 사유 한 줄)를 적는다. 같은 내용을 7절에도 갱신한다.

## 4. step별 상세

### R0 준비
- 할 일: `개발산출물/매력도_검토/컨센서스/{scripts,raw}` 만들기. 표본 확정 — 국내 대형 3(005930·000660·005380), 중형 2·코스닥 소형 2는 비교군에서 고른다(거래량 상위 캐싱 대상이 있으면 그중에서). 미국은 AAPL·NVDA, 중형 2, `005930.KS`. KIS 이용약관(시세·정보 표시·재배포 조건)과 yfinance/Yahoo 약관 요지, 과제 데모와 공개 서비스에서 달라지는 점. KIS 실전/모의 도메인 중 어느 쪽을 쓸지(`.env` 설정 확인, 값은 적지 않음)
- 결과: 표본표(코드·이름·시장·시총·선정 이유), 약관 요지와 출처 URL, 도메인
- 완료 기준: 표본 12종목 확정, 약관 항목마다 "확인/미확인(사유)"

### R1 yfinance 표본 호출
- 할 일: 요청서 2장 해외 8종 × 표본 5종목을 1회씩 호출하고 `raw/R1/`에 저장(JSON/CSV)
- 결과: 종목 × 엔드포인트 커버리지 표(값/None/빈 DataFrame/오류 구분), 필드명·의미·단위·기준 기간, `upgrades_downgrades`의 구분 필드·목표가 필드·날짜 범위, `get_recommendations()`의 기간 구조, 오류 원문

### R2 KIS 표본 호출
- 할 일: 포털·`open-trading-api`에서 3종의 TR ID·요청 파라미터·output 구조 확인 → 7종목 × 3종 1회 호출(`invest-opbysec`는 한국투자증권 + 다른 증권사 1곳), `raw/R2/` 저장. 초당 호출 제한, 모의 도메인 동작 여부 확인
