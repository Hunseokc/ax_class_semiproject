## 1. 결론 먼저

| API | 판정 | 한 줄 근거 |
|---|---|---|
| `invest-opinion` 종목투자의견 | **사용 가능** | 종목별 증권사 의견·목표가 이력(2016년 이전까지). 1회 최대 100건, 연속조회 없음 |
| `invest-opbysec` 증권사별 투자의견 | **사용 가능 — 변화 감지·수집의 주 경로** | `FID_INPUT_ISCD`에 **종목코드**(=`invest-opinion`과 같은 데이터 + 종목명·현재가), **3자리 회원사 코드**(`003`=한국투자: 그 증권사의 전 종목 의견), **`999`**(전 증권사·전 종목 의견 피드: 하루 54~129건)를 넣을 수 있다 |
| `estimate-perform` 종목추정실적 | **제한적** | **한국투자증권 애널리스트 1명의 추정**(시장 컨센서스 아님). 실적 3년 + 추정 2년. 표본 9종목 중 6종목만 값, **삼성전자·SK하이닉스는 실전 도메인에서도 빈 응답** |

### 앱키 경과

- 처음 `.env`의 `KIS_API_KEY`는 **모의투자 앱키**였다. 실전 도메인에서 `estimate-perform`·`invest-opbysec`는 `EGW02004 실전투자 도메인은 모의투자 앱키로 호출하실 수 없습니다.`(HTTP 500)로 거부됐고 `invest-opinion`만 통과했다. 모의 도메인(`https://openapivts.koreainvestment.com:29443`)에서는 3종 모두 응답했다.
- 같은 날 사용자가 실전 앱키를 발급해 `KIS_API_KEY`·`KIS_API_SECRET`에 넣고 기존 키는 `KIS_API_MOCK_KEY`·`KIS_API_MOCK_SECRET`으로 옮겼다. **실전 도메인에서 3종 모두 `rt_cd=0`**. 토큰은 키 끝 6자리가 달라 실전 키용으로 1회 새로 발급됐다(`backend/data/kis_token.json`). `KIS_PW`는 Open API 인증(앱키·시크릿)에 쓰이지 않아 맞는지 확인할 수 없다.
- 실전 vs 모의 응답: `estimate-perform` 5종목, `invest-opbysec` 2종목을 비교했더니 output이 **완전히 같다**(조회 시점 현재가 기준 필드 `stft_esdg`·`dprt`만 다름). 이 3종은 KIS 공식 Postman 샘플 중 **실전계좌 v2.6에만 있고 모의계좌 v1.6에는 없다** → 이후 수집은 실전 앱키·실전 도메인으로 한다.

### 호출 한도

- 모의 앱키: 0.25초 간격에서 `EGW00201 초당 거래건수를 초과하였습니다.` → 초당 1건.
- 실전 앱키: 0.1초 간격(응답 시간 포함 초당 약 5~6건) 10회 중 1회 `EGW00201`. 0.25~1.1초 간격 50회는 오류 0. 실전 공식 한도(초당 20건으로 알려짐)와 신규 발급 직후 제한 여부는 **미확인** → R3는 **0.5초 간격으로 시작하고 `EGW00201`이면 재시도**.

- **이어 받기 규칙(중요):** 100건에서 잘릴 때 마지막 날짜의 행이 일부만 들어온다. "끝 날짜 = 받은 최소 날짜 − 1일"로 이으면 그 날의 나머지가 **사라진다.** 한국투자(`003`) 12개월을 이 방식으로 8쪽 받은 뒤 쪽 경계일 7일만 따로 다시 받았더니 **27건이 빠져 있었다**(765 → 실제 792건). 예: 000660 2026-07-30 목표 4,700,000, 004370 2026-04-30 중립.
  → 규칙: **끝 날짜 = 받은 최소 날짜(포함)로 다시 호출하고 (날짜·종목·증권사·의견·목표가)로 중복 제거**, 새 행이 없으면 최소 날짜 − 1일로 넘어간다. 하루치가 100건 이상이면 `FID_DIV_CLS_CODE` 1·2·3으로 나눠 받는다(3-5).

### 3-6. 판정

- **사용 가능.** 국내 "증권사별 최신 의견·목표가"(요청서 A·B)의 원천으로 충분하다. 증권사별 최신 1건 집계, 목표가 평균·중앙값·괴리율을 직접 계산할 수 있다.
- 수집: 종목별은 `invest-opinion` 또는 `invest-opbysec`(종목코드) 어느 쪽이든 같다. 피드(`999`)·증권사별(`003`)은 `invest-opbysec`만 가능 → **`invest-opbysec` 하나로 통일**하는 안을 권한다(종목코드 필드가 있어 피드와 같은 파서).
- 주의: 직전 의견 필드·구분 코드 사용 금지, 목표가 0 = 결측, **경계일 포함 이어 받기 + 중복 제거**.

## 5. R3·R6에 넘길 것

- **앱키·도메인:** 실전 앱키(`KIS_API_KEY`), 실전 도메인. 0.5초 간격으로 시작, `EGW00201`이면 재시도.
- **R3 국내 수집:** `invest-opbysec` 하나로 — (가) 비교군 340종목 × 종목코드 입력(종목당 1~3쪽) 또는 (나) `999` 피드 12개월 하루 단위(약 250일 × 1~3회). 어느 쪽이든 **경계일 포함 이어 받기 + 중복 제거**, 하루 100건 이상이면 `FID_DIV_CLS_CODE` 1·2·3 분할. 빈 응답(`output: []`)은 "의견 없음"(실패 아님).
- **매핑표 입력 표기(현재까지):** `BUY`, `매수`, `Buy`, `Strong BUY`, `MARKETPERFORM`, `Outperform`, `중립`, `Hold`, `NotRated`, `분석대상제외`. 대소문자·공백 차이 정규화. `NotRated`가 한국투자에서 1/3을 넘으니 "미평가"로 따로 둔다.
- **R6:** 변화 감지는 `999` 피드 하루 1~3회가 가장 싸다(종목별 340회 대비). 증권사별 조회는 3자리 코드(`003` 확인, 나머지 코드는 마스터가 오래돼 미확인). `estimate-perform`은 연속조회 없음·종목당 1회, 바뀌었는지는 `estdate`로 판단.
- **R7 질문 후보:** ① `estimate-perform`을 "한국투자증권 추정"으로라도 표시할지(대형주 2종목 공백 포함) ② output3 추측 행을 포털 문서로 확정 ③ 실전 공식 호출 한도 확인.
- **앱 운영 메모(코드는 안 고침):** 실행 중인 `stockmind_api` 컨테이너는 시작할 때의 모의 키를 계속 쓴다. 같은 토큰 파일을 실전 키(이번 실행)와 모의 키(실행 중 api)가 번갈아 덮어써 서로 재발급하게 되므로, `.env` 교체를 반영하려면 api를 다시 띄운다(`docker compose up -d api`). `backend/app/providers/kis.py`의 `Throttle(1.05)` 주석("앱키가 모의투자로 발급")은 C3에서 실전 기준으로 고친다.
