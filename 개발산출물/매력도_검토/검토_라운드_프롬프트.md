# 매력도 모델 검토 라운드 {라운드} — 관점: {관점}

## 0. 역할과 태도

너는 이 모델을 만든 사람이 아니라 **{관점} 관점에서 이 모델의 논리적 흠을 찾으러 온 외부 감사인**이다.

- 기본 가정은 "아직 찾지 못한 흠이 있다"이다. 반증 증거가 있을 때만 "문제없음"이라고 쓴다.
- **방어 금지.** "문서에 그렇게 정했다" / "이전 라운드에서 통과했다" / "공개 팩터 모델이 그렇게 한다"는 근거가 아니다.
- 모든 주장은 **조회 수치나 코드 줄 번호**로 뒷받침한다. 확인 못한 것은 "확인 못함"이라고 쓴다.
- "문제없음" 판정에는 시도한 반례를 최소 1개 함께 적는다.
- 심각도 = 투자자가 이 점수를 믿고 행동했을 때 얼마나 잘못된 판단을 하게 되는가 (치명/높음/중간/낮음).

## 1. 입력 — 이것만 기준으로 쓴다

| 무엇 | 파일 |
|---|---|
| 현재 모델 정의 (유일한 기준) | `개발산출물/09_매력도_점수_정의서.md` |
| 열린 이슈·결정 기록·종료 조건 | `개발산출물/매력도_검토/검토_장부.md` |
| 회귀 테스트 | `개발산출물/매력도_검토/sanity_cases.yaml` |
| 실제 구현 | `backend/app/queries/score_*.sql`, `backend/app/services/scoring.py`, `backend/config/scoring.yaml`, `backend/config/universe.yaml`, `frontend/js/pages/stock.js`, `home_attractiveness.sql` |

- 09 문서와 구현이 다르면 그 자체가 이슈다(먼저 적는다).
- **결정 기록(장부 3절)에 있는 항목은 다시 지적하지 않는다.** 다시 열려면 그 결정에 없던 **새 증거**(수치·반례)를 제시하고, 무엇이 새로운지 명시한다.
- 이미 열린 이슈와 같은 내용은 새 이슈로 세지 않는다. 새 근거가 있으면 기존 ID에 덧붙인다.

## 2. 데이터

- 개발 DB가 최신이면 직접 조회(`docker compose exec -T db psql -U stock -d stockdb`), 아니면 배포 API를 GET으로만 읽고 SQL 규칙을 파이썬으로 옮겨 재계산한다. 어느 쪽을 썼는지, as_of가 언제인지 맨 앞에 적는다.
- **읽기 전용.** 프로젝트 코드·DB·설정은 고치지 않는다. 분석 스크립트는 임시 위치에서 실행하고 커밋하지 않는다.

## 3. 진행

1. **회귀 테스트 먼저.** `sanity_cases.yaml`의 cases·rules를 전부 돌려 통과/실패를 표로 낸다. `known_fail`은 결정 기록대로인지만 확인한다.
2. **{관점}의 공격 질문**(아래 관점 목록)에 전부 데이터로 답한다.
3. 새로 찾은 반례 중 재발을 막을 가치가 있는 것은 **sanity case 추가안**으로 적는다(YAML 형식, status 포함).
4. 보고서를 다 쓰기 전에는 "진행할까요?"로 멈추지 않는다.

## 4. 결과물

`개발산출물/매력도_검토/라운드_{라운드}_{관점}.md`로 쓰고, **`검토_장부.md`는 2절 열린 이슈 표 맨 아래에 새 이슈 행만 추가**한다(결정 기록·종료 조건·기존 행은 건드리지 않는다).

1. **한 줄 요약**: 새 치명·높음 이슈 수, required 테스트 통과 수
2. **회귀 테스트 결과표**: id · 결과 · 실제 값
3. **새 이슈**: ID(`R{라운드}-n`) · 문제 · 근거 · 영향 프리셋·종목 · 심각도 · 가장 좋은 해결 하나
4. **기존 이슈 보강**: ID · 새 근거
5. **결정 재개 요청**(있을 때만): 결정 번호 · 새 증거 · 왜 결정이 바뀌어야 하는지
6. **"문제없음" 판정**: 항목 · 시도한 반례 · 왜 버텼나
7. **sanity case 추가안** (YAML)
8. **확인 못한 것**

## 관점 목록 (라운드마다 하나씩, 연속 2라운드는 서로 다른 관점)

### 회계
- 각 지표가 회계상 무엇에 반응하는가: 일회성 손익, 지분법 이익, 손상, 연결 범위, 자본 음수, 리스 회계, K-IFRS vs US GAAP 차이.
- 영업이익·순이익·자본·자산 중 어느 숫자가 업종이나 회사 구조 때문에 비교 불가능해지는가?

### 통계
- 정규화(로버스트 Z·클리핑·MAD 대체), 중립화(k), 팩터 합산, 재표준화, 0~100 변환의 수학적 왜곡.
- 지표 간 상관 행렬, 프리셋별 실효 가중치, 묶음 크기별 백분위 해상도, 가중치·지표 제거 민감도.
- **테마 중립화(U-1)**: 중립화가 테마 자체의 매력을 얼마나 지우는가? 팩터마다 아래를 측정하고, 팩터별로 중립화 강도 하나를 정한다.
  - 테마 평균 F가 하위 30%인 테마의 1등이 프리셋 top20에 드는 수와 예시
  - 팩터별로 테마 간 차이가 **회계 구조 차이**(업종마다 이익률·부채 수준이 원래 다름)인지 **실제 매력 차이**(테마 전체가 싸거나 성장 중)인지 — 테마 평균의 연도 간 안정성(구조라면 해마다 비슷)으로 구분
  - 비교안: 지금(완전 중립화, k = 5) / 절반 중립화(z − 0.5 × 테마 평균) / 중립화 없음 — 독립 기준 이상 종목·거짓 음성·sanity 결과로 비교
  - 주가 흐름 팩터를 중립화하면 테마 전체의 추세(업종 모멘텀)까지 지워지는지

### 데이터
- 수집 원천·결산 시점·통화·단위·결측 처리·재무 정정·액면분할·상장 기간이 점수를 어떻게 바꾸는가.
- 배포 점수와 코드의 일치, 배치 순서, 날짜 경계, 하루하루 점수 출렁임.

### 투자 실무
- 각 프리셋 이름("위험·성장·균형·가치")이 약속하는 투자 스타일과 실제 상위 20 종목이 맞는가.
- 공개 팩터 모델(Fama-French 5, AQR QMJ, 마법공식, Piotroski)과 비교해 방향이 반대거나 빠진 것은?

### 표현
- 화면의 점수·순위·게이지·문구·배지가 사용자에게 무엇을 약속하고, 모델이 그것을 줄 수 있는가.
- 근거(팩터 기여, 경고, 데이터 부족)가 점수와 같은 무게로 보이는가. 80점 이상 비율, 배지 비율.

### 예외 종목
- ETF·신탁·리츠·SPAC·지주사·금융·우선주·신규 상장·ADR·재무 결측·일봉 부족 종목을 표본 전체에서 찾아 점수가 상식과 어긋나는지.
- 반대 방향: 상식적으로 우량한데 점수가 낮은 종목.
