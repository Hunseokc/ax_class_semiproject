## 1. pykrx 시총·펀더멘털·지수 빈 결과

### 발생 일시·담당자·영향 범위
- **발생 일시**: 확인 필요 — 1단계 smoke test 중 발견. 해결이 담긴 첫 커밋은 `a57b684`(2026-10-06 23:06, 초기 구현), 재실행 결과 기록은 `bedec97`(2026-10-07 10:36, `docs/smoke_test_result.md`)
- **담당자**: Hunseokc (커밋 작성자)
- **영향 범위**: 국내 밸류에이션(시총·PER·PBR·EPS·BPS) 전 종목, 국내 지수(KOSPI·KOSDAQ). 일봉·종목명은 정상이라 "부분적으로만 실패"해 발견이 늦어질 수 있는 유형

### 문제 상황
- **기능**: 국내 밸류에이션 적재(`valuation`), 지수 적재(`indices`)
- **영향**: 시총·PER/PBR이 비어 매력도의 가치 팩터와 원화 환산 시총 순위를 계산할 수 없음
- **오류 메시지**: 시총·펀더멘털은 예외 없이 빈 DataFrame, 지수는 `KeyError: '지수명'` (ASSUMPTIONS A-01)

### 원인 분석
- **직접 원인**: pykrx 1.2.x는 KRX 정보데이터시스템의 시총·펀더멘털·지수 화면에 **회원 로그인**이 필요하다. 로그인하지 않으면 해당 엔드포인트가 빈 응답을 준다.
- **근본 원인**: pykrx는 **import 시점**에 `os.environ`의 `KRX_ID`/`KRX_PW`를 읽는다. `.env`에 값을 넣어도 pydantic-settings가 읽을 뿐 환경변수로 내보내지 않으면 pykrx는 로그인하지 못한다(A-04). 또한 비공식 라이브러리라 사이트 정책 변화가 그대로 영향을 준다.
- **확인 방법**: `python -m app.ingest.smoke`로 로그인 없음/있음 두 경우의 실제 응답을 비교(`docs/smoke_test_result.md`), pykrx 소스 `website/comm/auth.py`에서 환경변수 읽는 시점 확인

### 해결 과정
1. smoke test로 로그인 여부에 따른 응답 차이를 실측해 원인을 로그인으로 좁힘
2. `export_krx_credentials()`(`app/core/config.py`)로 `.env` 값을 **pykrx import 전에** 환경변수로 내보내도록 함
3. 로그인 세션 만료(1시간)는 pykrx가 자동 재로그인함을 소스로 확인(A-05)
4. 장애 대비: `PRICE_SOURCE_KR=yfinance`로 국내 소스를 바꿀 수 있게 하고(A-03), pykrx 실패 시 DART FY 기반 파생 밸류에이션(`DERIVED`)으로 대체(A-02)

### 해결 결과
- **정상화**: 로그인 후 일봉·시총·펀더멘털·지수가 모두 동작. 2026-10-08 운영 DB 기준 PYKRX 밸류에이션 4,096행, 국내 지수 3종 각 487행(`docs/03` 5-1)
- **재발 확인 방법**: `python -m app.ingest.smoke` 재실행, `GET /api/v1/statistics/data-quality`에서 VALUATION·INDICES의 `last_failure_reason`, `python -m app.ingest status`의 최근 실패

### 재발 방지
- **코드**: `export_krx_credentials()` 호출을 pykrx import 경로 앞에 고정, 소스 전환(`PRICE_SOURCE_KR`)·DERIVED 폴백 유지
- **점검 항목**: README 환경변수 표에 `KRX_ID`·`KRX_PW`를 pykrx 사용 시 **필수**로 표시, 장애 시 점검 순서에 "KRX 로그인" 포함(README 운영 가이드)
- **문서**: ASSUMPTIONS A-01~A-05, `docs/03` 1절, `docs/smoke_test_result.md`

## 2. 다른 사용자의 포트폴리오에 접근 가능 (소유권 검증 누락)

### 발생 일시·담당자·영향 범위
- **발생 일시**: 확인 필요 — 수정 커밋 기준 2026-10-07 10:07~10:10 (`3f65cb5` user_id 파라미터 제거·`get_current_user_id` 도입, `bca446f` 소유자 확인·남의 리소스 404, `e5cdcd9` 프론트 user_id 전송 제거)
- **담당자**: Hunseokc (커밋 작성자)
- **영향 범위**: 포트폴리오 CRUD 전체(단건·수정·삭제·요약·항목 목록·담기·항목 수정·삭제), 관심종목 삭제·정렬. 1차는 로컬·시연 전용이라 외부 노출은 없었음

### 문제 상황
- **기능**: `/api/v1/portfolios/{portfolio_id}`·하위 경로, `/api/v1/watchlist`
- **영향**: `portfolio_id`만 알면 다른 사용자의 포트폴리오를 조회·수정·삭제할 수 있었음(IDOR). 사용자 구분이 클라이언트가 보낸 `user_id`에 달려 있었음
- **오류 메시지**: 없음 — 정상 200으로 남의 데이터가 반환되는 유형이라 오류로 드러나지 않음

### 원인 분석
- **직접 원인**: API가 쿼리·본문의 `user_id`를 그대로 신뢰했고, 포트폴리오 단건 조회에 소유자 조건(`user_id = 요청 사용자`)이 없었음
- **근본 원인**: 인증을 2차로 미루면서 "요청 사용자"를 정하는 지점이 서버에 없었음. 사용자 식별이 클라이언트 입력에 흩어져 있었음
- **확인 방법**: 사용자 2명을 시드한 뒤 사용자 1로 사용자 2의 리소스에 접근하는 교차 접근 테스트를 먼저 작성해 재현(`tests/test_ownership.py`)

### 해결 과정
1. 교차 접근 테스트로 문제를 재현(수정 전 실패 확인)
2. API에서 `user_id` 파라미터를 제거하고 서버 의존성 `get_current_user_id()`로 요청 사용자를 정함 — 1차는 `DEFAULT_USER_ID`, 2차에서 JWT 검증으로 이 함수만 교체(A-57)
3. 서비스 계층이 요청 사용자 소유만 조회하고, 남의 리소스는 존재 여부를 드러내지 않도록 없는 리소스와 같은 404(`PORTFOLIO_NOT_FOUND`·`ITEM_NOT_FOUND`·`WATCHLIST_ITEM_NOT_FOUND`) (A-82)
4. 내 포트폴리오 경로에 남의 항목 ID를 넣는 우회도 막음(`ITEM_NOT_FOUND`)

### 해결 결과
- **정상화**: 교차 접근 11건(2026-10-08 관심종목 메모 수정 PUT 추가 포함) 모두 404, 사용자 2의 데이터 변화 없음
- **재발 확인 방법**: `pytest tests/test_ownership.py` — `docs/07` USR-02~05. 새 엔드포인트를 만들면 `CROSS_REQUESTS`에 한 줄 추가

### 재발 방지
- **코드**: 요청 사용자는 `get_current_user_id()` 한 곳에서만 결정(라우터는 `user_id`를 받지 않음), 서비스 조회에 항상 소유자 조건
- **점검 항목**: 새 엔드포인트 추가 시 교차 접근 테스트 케이스 추가(작업 지시서 단계 G에서 PUT /watchlist 추가로 적용)
- **문서**: ASSUMPTIONS A-57·A-82, `docs/06` 1절 인증·소유권, `docs/02` REQ-USR-01·02

## 3. 어떤 투자 성향을 골라도 Tesla 매력도가 2~3점

### 발생 일시·담당자·영향 범위
- **발생 일시**: 확인 필요 — 다중 팩터 모델 도입(`74a6f84`, 2026-10-07 11:19) 이후 발견, 수정 커밋 `e00c93b`(12:37, 같은 국가끼리 중립화)·`fa0376f`(14:43, 매력도 비교군 도입)
- **담당자**: Hunseokc (커밋 작성자)
- **영향 범위**: 미국 종목 전체의 매력도(특히 표본 안 하위 종목), 국내 자동차 그룹. 화면의 매력도 게이지·순위·포트폴리오 가중 매력도

### 문제 상황
- **기능**: 매력도 점수(`app/services/scoring.py`, `score_*.sql`, docs/09)
- **영향**: 투자 성향(위험·성장·균형·가치)을 바꿔도 Tesla가 항상 2~3점 — 성향 선택이 의미 없어 보이고, 점수가 "상대적 위치"가 아니라 "표본이 작아서 생긴 극단값"이 됨
- **오류 메시지**: 없음 — 계산은 정상 종료, 결과 분포가 비정상

### 원인 분석
- **직접 원인**: 미국 비교 표본이 초대형 기술주 9개뿐이라, 국가 안 로버스트 Z에서 꼴찌가 0점 근처로 쏠림
- **근본 원인**: (1) 표본 설계 — 화면 노출 종목만으로 점수를 매겨 비교 대상이 너무 적고 한쪽으로 치우침 (2) 섹터 중립화가 국가를 섞어, 국내 자동차의 저평가 Z가 Tesla가 속한 그룹 평균에 들어감(z는 국가 안에서 표준화한 값이라 국가가 다른 값의 평균은 의미가 없음)
- **확인 방법**: 팩터 기여도·지표 원값/Z 표(`/stocks/NASDAQ/TSLA/analysis`)로 어느 팩터가 점수를 끌어내리는지 확인, 그룹 평균 계산에 들어간 구성원 국가 확인

### 해결 과정
1. 섹터 중립화의 그룹 평균을 **같은 국가 구성원끼리만** 계산(`e00c93b`, docs/09)
2. 국가별·섹터별 시가총액 상위 10개로 **매력도 비교군(121종목)** 도입 — 점수 표본을 넓힘(`fa0376f`, A-100~A-103)
3. 비교군 운영 부담 대응: 평시 필수 데이터만 1일 갱신, 상세는 요청 시 수집, DART 분당 제한 보호(60초 90회), 앱 안 스케줄러

### 해결 결과
- **정상화**: Tesla 2.40점(미국 9개 중 꼴찌) → 28.69점(미국 76개 중 62위). PER 약 350배·매출 감소·낮은 이익률이라 여전히 하위권이지만, 표본 안 상대 위치로 해석 가능한 값이 됨(docs/09)
- **재발 확인 방법**: `pytest tests/test_scoring.py tests/test_benchmark.py` — `docs/07` SC-04·SC-18(중립화 국가 분리), BM-01(비교군 선정). 화면 확인 UI-44("미국 비교군 76개 중 62위")

### 재발 방지
- **코드**: 중립화 그룹 평균은 국가 조건 포함, 비교군 선정은 30일마다 실제 시가총액으로(경계 종목 흔들림 방지, A-101)
- **점검 항목**: 표본이 작은 국가·섹터 조합은 점수 분포를 확인(미국 2차전지처럼 적자 소형주가 많은 그룹은 상위 종목 점수가 크게 오를 수 있음 — A-107)
- **문서**: docs/09(지표 정의·중립화·비교군), ASSUMPTIONS A-100~A-107
