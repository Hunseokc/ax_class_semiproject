## 2. 상세 정의

### D1·D2. 종목 일봉 (→ `daily_prices`)
- 원본 컬럼(pykrx `get_market_ohlcv(adjusted=True)`, 확인): index `날짜`, `시가`, `고가`, `저가`, `종가`, `거래량`, `등락률`
- 원본 컬럼(yfinance `Ticker.history(auto_adjust=True)`, 확인): index `Date`(tz-aware: KR `Asia/Seoul`, US `America/New_York`), `Open`, `High`, `Low`, `Close`, `Volume`, `Dividends`, `Stock Splits`
- 실측 규모(yfinance 2년): KR 485행, US 500행/종목 (2024-10-07 ~ 2026-10-06)

| DB 컬럼 | 타입 | 원본 | 설명 |
|---|---|---|---|
| stock_id | INT | (매핑) | `stocks` FK |
| trade_date | DATE | 날짜 / Date | 시장 현지 날짜 |
| open/high/low/close | NUMERIC(18,4) | 시가… / Open… | **수정주가** |
| volume | BIGINT | 거래량 / Volume | 주식 수, ≥ 0 |

- 전처리: 수정주가 통일, tz → 현지 date, (stock_id, trade_date) 중복 제거, OHLC 결측 행 제외, `high < low`·`close ≤ 0`·`volume < 0` 행은 격리 후 `ingestion_logs`에 사유 기록, 장 마감 전 당일 봉 제외
- 사용하지 않는 컬럼: `등락률`(VIEW에서 LAG로 재계산), `Dividends`, `Stock Splits`

### D3. 지수 일봉 (→ `index_daily_prices`)
- pykrx `get_index_ohlcv`(확인): `시가`, `고가`, `저가`, `종가`, `거래량`, `거래대금`, `상장시가총액` → OHLC만 사용
- yfinance(확인): `Open`, `High`, `Low`, `Close`(+`Volume` 미사용)

| DB 컬럼 | 타입 | 설명 |
|---|---|---|
| index_id | SMALLINT | `indices` FK |
| trade_date | DATE | 현지 날짜 |
| open/high/low | NUMERIC(18,4) | NULL 허용 |
| close | NUMERIC(18,4) | 필수 |

### D4. USD/KRW 환율 (→ `fx_rates`)
- yfinance `KRW=X`(확인): `Close` 사용. 인덱스 tz `Europe/London`, 2년 517행(외환시장 영업일 기준이라 주식보다 많음)

| DB 컬럼 | 타입 | 설명 |
|---|---|---|
| rate_at | TIMESTAMPTZ | DAILY: 해당 일자 00:00 Asia/Seoul, SNAPSHOT: 조회 시각 |
| usd_krw | NUMERIC(12,4) | 1달러당 원, > 0 |
| granularity | VARCHAR(8) | SNAPSHOT / DAILY |
| source | VARCHAR(20) | YFINANCE |

### D5. 밸류에이션 — 국내 (→ `valuation_snapshots`, source=`PYKRX`)
- pykrx `get_market_fundamental`(확인): `BPS`, `PER`, `PBR`, `EPS`, `DIV`, `DPS` (일별)
- pykrx `get_market_cap`(확인): `시가총액`, `거래량`, `거래대금`, `상장주식수` (일별)
- 두 결과를 날짜로 결합해 최근 1년 일별 적재. PER/PBR 0 이하·EPS/BPS 0은 NULL(KRX의 산출 불가 표기, A-37)
- 대체(DERIVED): EPS = 지배주주 순이익 / 상장주식수, BPS = 지배주주 자본 / 상장주식수 (DART 최신 FY), PER = 종가/EPS, PBR = 종가/BPS

### D6. 밸류에이션 — 미국 (→ `valuation_snapshots`, source=`YFINANCE`)
- yfinance `Ticker.info`(확인): `marketCap`, `trailingPE`, `priceToBook`, `trailingEps`, `bookValue`, `sharesOutstanding`, `currency` (AAPL·NVDA 값 존재). 적재 시점 1행 스냅샷
- 참고: yfinance는 KR 종목의 `trailingPE`·`priceToBook`·`trailingEps`·`bookValue`가 None(확인) → KR은 pykrx 사용

| DB 컬럼 | 타입 | KR 원본 | US 원본 |
|---|---|---|---|
| as_of | DATE | 날짜 | 적재일(현지) |
| per | NUMERIC(18,4) | PER | trailingPE |
| pbr | NUMERIC(18,4) | PBR | priceToBook |
| eps | NUMERIC(18,4) | EPS | trailingEps |
| bps | NUMERIC(18,4) | BPS | bookValue |
| market_cap | NUMERIC(26,0) | 시가총액 | marketCap |
| shares_outstanding | BIGINT | 상장주식수 | sharesOutstanding |

### D7. 재무 FY — 국내 (OpenDART → `financial_statements`)
- API: `GET /api/fnlttSinglAcntAll.json` (`crtfc_key`, `corp_code`, `bsns_year`, `reprt_code=11011` 사업보고서, `fs_div=CFS` 연결)
- 확인: 16개 종목 × 2021~2025 모두 status=000
- 원본 필드(공식 문서 기준): `rcept_no`, `bsns_year`, `sj_div`, `account_id`, `account_nm`, `thstrm_amount`, `frmtrm_amount`, `bfefrmtrm_amount`, `currency`
- 계정 매핑(account_id 우선 → account_nm 대체, ASSUMPTIONS A-13):

| DB 컬럼 | account_id 1순위 | 대체 |
|---|---|---|
| revenue | `ifrs-full_Revenue` | 계정명 매출액 / 영업수익 / 수익(매출액) |
| operating_income | `dart_OperatingIncomeLoss` | 계정명 영업이익(손실) |
| net_income | `ifrs-full_ProfitLossAttributableToOwnersOfParent`(지배주주) | `ifrs-full_ProfitLoss` |
| total_assets | `ifrs-full_Assets` | 계정명 자산총계 |
| total_equity | `ifrs-full_EquityAttributableToOwnersOfParent`(지배주주) | `ifrs-full_Equity` |
| total_debt | `ifrs-full_Liabilities`(부채총계) | 계정명 부채총계 |

- `total_debt`는 부채총계로 정의한다(차입금만이 아님) — 미국도 같은 정의로 맞춘다(Liabilities)
- `accounting_std='K-IFRS'`, `data_source='DART'`, `period_type='FY'`, `period_end`=결산일

### D8. 재무 FY — 미국 (SEC companyfacts → `financial_statements`)
- API: `GET https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json` (API 키 없음, `User-Agent` 필수)
- 구조: `facts.us-gaap.<concept>.units.USD[]` → `start`, `end`, `val`, `accn`, `fy`, `fp`, `form`, `filed`, `frame`
- 확인(AAPL): `Revenues`, `RevenueFromContractWithCustomerExcludingAssessedTax`, `OperatingIncomeLoss`, `NetIncomeLoss`, `Assets`, `StockholdersEquity`, `LongTermDebt` 존재. NetIncomeLoss 10-K FY 결산일 2020~2025
- FY 선택: `form='10-K'`, `fp='FY'`, 기간(start~end) 약 1년 항목, 같은 `end`가 여러 번이면 최신 `filed`
- 매핑: revenue = `Revenues` → `RevenueFromContractWithCustomerExcludingAssessedTax`, operating_income = `OperatingIncomeLoss`, net_income = `NetIncomeLoss`, total_assets = `Assets`, total_equity = `StockholdersEquity`, total_debt = `Liabilities`
- 누락값은 yfinance `income_stmt`/`balance_sheet`(확인: `Total Revenue`, `Operating Income`, `Net Income`, `Total Assets`, `Stockholders Equity`, `Total Debt` 존재, 연간 4개 기간)로 보완
- `accounting_std='US-GAAP'`, `data_source='SEC'`(보완 행은 `YFINANCE`)

### D9. 공시 — 국내 (OpenDART `list.json` → `disclosures`)
- 확인 필드: `corp_code`, `corp_name`, `stock_code`, `corp_cls`, `report_nm`, `rcept_no`, `flr_nm`, `rcept_dt`, `rm`
- 실측: 삼성전자 최근 1년 전체 2,851건 중 2,730건이 지분공시(D, 임원·주요주주 소유 보고) → **지분공시 제외** 유형 A·B·C·E·F·I만 적재(ASSUMPTIONS A-36), `last_reprt_at=Y`, `page_count=100` 페이지 반복
- report_type에는 공시유형명(정기공시·주요사항보고·발행공시·기타공시·외부감사관련·거래소공시)을 저장
- 매핑: `rcept_no`→rcept_no, `report_nm`(공백 정리)→title, 공시유형명→report_type, `rcept_dt`(YYYYMMDD)→filed_at 00:00 Asia/Seoul, url=DART 뷰어

### D10. 공시 — 미국 (SEC `submissions` → `disclosures`)
- 확인 필드 `filings.recent`: `accessionNumber`, `filingDate`, `reportDate`, `acceptanceDateTime`, `act`, `form`, `fileNumber`, `filmNumber`, … (AAPL recent 1,000건)
- 수집 서식: 10-K·10-Q·8-K(각 /A)·DEF 14A·S-3·S-3ASR·S-8·SD·11-K (Form 4 등 내부자 지분 보고 제외)
- 매핑: `accessionNumber`→rcept_no, `form`→report_type, title=`primaryDocDescription`(form과 같으면 form, 8-K는 `8-K (Item 2.02, …)`), `acceptanceDateTime`→filed_at, url=`/Archives/edgar/data/{cik}/{accession}/{primaryDocument}`

### D11. 식별자 매핑 (→ `stocks.corp_code`, `stocks.cik`)
- DART `corpCode.xml`(확인): 전체 119,546개 법인, 16/16 매핑. 필드 `corp_code`, `corp_name`, `stock_code`, `modify_date`
- SEC `company_tickers.json`: `cik_str`, `ticker`, `title`. 이메일이 포함된 `SEC_USER_AGENT`가 필요(연락처 없는 UA는 403 확인)

## 4. 이용 조건 (README에도 명시)
- pykrx: KRX 정보데이터시스템 비공식 라이브러리. 1.2.x는 시총·펀더멘털·지수에 KRX 회원 로그인이 필요(세션 1시간).
- yfinance: Yahoo Finance 비공식 라이브러리. 개인·학습 목적으로 사용하며 원본을 재배포하지 않는다. 저장소에는 소량 샘플만 커밋.
- OpenDART: 금융감독원 공식 Open API, 인증키 필요, 일일 호출 한도 있음.
- SEC EDGAR: 공식 공개 API, API 키 없음, 연락처 포함 User-Agent 필수, 초당 10건 이하 권고.
