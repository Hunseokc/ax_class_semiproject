# 01. 프로젝트 기획서

## 1. 프로젝트명
**주식 분석 대시보드 (가칭)** — 국내·미국 주식 데이터 백엔드와 대시보드

## 2. 배경
- 개인 투자자는 국내(KRX)와 미국(NASDAQ) 종목을 함께 보지만, 시세·지수·환율·재무·공시가 서로 다른 사이트와 통화, 회계기준에 흩어져 있다.
- 종목 하나를 판단하려면 같은 업종의 경쟁 종목과 비교해야 하는데, 국내·해외 종목을 한 화면에서 같은 기준(원화 환산, 기간 수익률 등)으로 비교하기 어렵다.
- "이 시드로 이 종목들을 담으면 얼마가 남고, 환율이 바뀌면 손익이 어떻게 되는가"를 계산하려면 지금은 엑셀로 직접 계산해야 한다.

## 3. 문제 정의
| # | 문제 | 해결 방향 |
|---|---|---|
| P1 | 출처마다 형식·통화·시간대가 다른 원천 데이터 | 수집·전처리 후 PostgreSQL 정규화 스키마로 통합 (시장 단위 속성 분리) |
| P2 | 수익률·변동성·MDD 같은 파생 지표를 매번 수작업으로 계산 | SQL VIEW(`v_stock_metrics`)로 일관되게 계산 |
| P3 | 국내·해외 경쟁 종목 비교가 어려움 | 경쟁 그룹(N:M) + 윈도우 함수(RANK, AVG OVER) 비교, 기준일=100 환산 차트 |
| P4 | 시드 기반 모의 배분 계산의 번거로움 | 담은 시점 가격·환율을 고정 저장하는 장바구니형 모의 포트폴리오 |
| P5 | 외부 API 호출 비용·차단 위험 | TTL(3~4시간) 기반 갱신 정책, advisory lock으로 중복 호출 방지 |

## 4. 목적
1. 원천 데이터를 **재현 가능한 적재 파이프라인**으로 PostgreSQL에 구조화한다.
2. 정규화·제약조건·인덱스·VIEW를 갖춘 DB 설계와 분석 SQL(JOIN, GROUP BY, HAVING, 윈도우 함수, CTE)을 구현한다.
3. FastAPI로 조회·분석·CRUD API를 제공하고, 바닐라 HTML/CSS/JS 대시보드로 시각화한다.

## 5. 대상 사용자
- 국내·미국 주식을 함께 관심 있게 보는 개인 투자 입문자
- 경쟁 종목 간 지표를 빠르게 비교하고 싶은 사용자
- 실제 매매 전에 시드 배분을 시험해 보려는 사용자
- 1차는 **로그인 없는 단일 사용자(데모) 모드**이며 로컬·시연 전용이다. 모든 요청은 설정값 `DEFAULT_USER_ID`(기본 1 = demo) 사용자로 처리하고, 포트폴리오·관심종목은 소유자만 접근하도록 확인한다(남의 리소스는 404). 로그인은 2차에서 요청 사용자를 정하는 `get_current_user_id()`를 JWT 검증으로 교체해 도입한다

## 6. 주요 기능
| 화면 | 기능 |
|---|---|
| 대시보드 홈 | 주요 지수 5개·USD/KRW 카드(30일 스파크라인), 관심종목 카드, 거래량 상위 5종목 |
| 주식 리스트 | 시장 탭, 거래량/시가총액 순위, 검색·경쟁 그룹 필터, ★ 관심 토글, 포트폴리오 담기 |
| 종목 상세 | 가격 차트, 핵심 지표, 매력도(프리셋별 점수·팩터 기여도·지표 원값/Z·국가 내 순위), 수치 분석, FY 재무 추이, 경쟁 종목 비교, 최근 공시 |
| 모의 포트폴리오 | 시드 설정, 수량/금액/비중 모드로 담기, 시드 초과 방어, 요약(환 효과 분리)·비중 차트 |
| 공통 | 일봉 기준·마지막 갱신 시각 표시, TTL 기반 새로고침 |

## 8. 기대 효과
- 흩어진 데이터를 하나의 정규화된 DB로 통합하는 데이터 백엔드 설계·구현 경험
- 파생 지표·상대 평가를 SQL로 계산해 재현성과 검증 가능성 확보(손계산 테스트)
- 확장 기반: Provider 인터페이스, `users` 테이블, 요청 사용자 의존성 `get_current_user_id()`(2차에서 JWT 검증으로 교체), JSON 구조의 분석 결과 → 2차(로그인·React), 3차(LLM 보고서) 확장 용이
