## 10. 사용자·접근 (USR)
1차는 **로그인 없는 단일 사용자(데모) 모드**이며 로컬·시연 전용이다. 인증(로그인·JWT)은 1차 범위 밖이다.

| REQ-ID | 요구사항 | 중요도 | 상태 |
|---|---|---|---|
| REQ-USR-01 | 요청 사용자는 서버 의존성 `get_current_user_id()`가 정한다. 1차는 설정값 `DEFAULT_USER_ID`(기본 1 = demo)를 반환하고, API는 클라이언트가 보낸 `user_id`(쿼리·본문)를 받지 않는다 | 필수 | 완료 (USR-01, WL-05) |
| REQ-USR-02 | 포트폴리오·담은 항목·관심종목은 요청 사용자 소유만 조회·변경하고, 다른 사용자의 리소스는 존재 여부를 드러내지 않도록 404로 응답한다 | 필수 | 완료 (USR-02~05 — 사용자 2명 시드, 교차 접근 13건) |
| REQ-USR-03 | 로그인 도입: `get_current_user_id()`를 JWT 검증으로 교체(라우터·서비스는 변경 없음) | 선택 | 미구현 (2차 범위) |

## 11. 요약
- 필수 요구사항: 모두 구현·검증 완료
- 1차는 단일 사용자(데모) 모드(로컬·시연 전용). 로그인은 2차에서 `get_current_user_id()`를 JWT 검증으로 교체한다(USR-03)
- 선택 요구사항 중 미구현: 분기 재무(DATA-12), 투자 스타일 체크리스트(STK-11), 시나리오 API(PF-13), 균등 배분 미리보기(PF-14). 관심종목 정렬 변경(WL-03)은 API만 구현
- 미구현 항목은 명세 12절의 '일정이 밀리면 줄이는 순서'에 해당하며, DB·SQL·테스트·문서는 줄이지 않았다
