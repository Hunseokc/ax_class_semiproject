# 단계별 로드맵 — 원본 분해표 (시니어용)

원본 파일 하나하나가 **어느 단계, 누구 파트**에서 처음 등장하는지 정리한 표다. 단계 순서는 원본 커밋 히스토리의 실제 순서(초기 구현 → 매력도 v2 → 비교군 → 메모·통계 → 상장 검색 → 홈 개편)와 마이그레이션 번호(001~007)가 자연스럽게 이어지도록 맞췄다.

- 경로는 모두 레포 루트 기준. `be/` = `backend/`, `fe/` = `frontend/`
- **공유 파일**은 여러 단계·여러 사람이 조금씩 키운다. 담당 구역 주석 `# ── [S{N}-{X}] ──` 아래에만 추가한다.
  - `be/app/schemas/api.py` · `be/app/main.py`(라우터 등록 1줄) · `be/app/api/deps.py` · `be/app/ingest/__main__.py`(CLI 하위 명령) · `be/app/ingest/jobs.py` · `fe/js/api.js` · `fe/js/pages/stock.js` · `fe/js/pages/home.js`
- **스키마(`be/db/schema.sql`)·ORM(`be/app/models/__init__.py`)은 D 단독 소유.** 단계 시작 시 D가 그 단계 테이블을 먼저 추가해 "계약"으로 배포한다(인터페이스 먼저 원칙).
- 원본의 `schema.sql`은 최종 형태다. D는 단계마다 그 단계 테이블·컬럼만 잘라 넣고, Stage 4부터는 원본과 같은 번호의 마이그레이션 파일도 함께 추가한다.

## 시니어 통합 체크리스트 (단계마다)

1. 단계 시작 전: `team/contracts/stage{N-1}.toml`을 복사해 `stage{N}.toml` 작성(이번 단계 consumers·planned·skip_import, 이번에 추가되는 항목은 exclude에서 삭제) → schema·ORM·deps·config를 원본에서 **복사 후 뺄 것만 삭제** → `python team/tools/check_contract.py {N}` 통과 → schemas 구역·main.py 라우터 자리 커밋 → `stage{N}` 브랜치 생성 → 프롬프트 배포
   - 프롬프트에 적는 이름(스키마 클래스·함수·필드)은 원본에서 복사한다. 계약 검사의 planned 목록과 프롬프트의 [담당 파일]이 같은 이름인지 확인한다.
2. PR 리뷰: 담당 외 파일 변경 없음 / 범위 밖 기능 없음 / "핵심 개념"(본인이 고른 답)이 채워졌는지 / "🔌 연결 목록"이 `TODO(연결)`과 맞는지 / CI(pytest) 초록 / `check_contract.py {N}` 통과
3. 머지 순서: **C(데이터) → B(API) → A(화면)** — 아래층부터 올려야 충돌·깨짐이 적다. PR은 파트 단위로 작게 오므로 CI가 통과한 Ready PR은 당일 머지한다.
4. 🔌 연결: 단계 PR이 모두 머지되면 stage에서 `git grep -n "TODO(연결)"` → 각 PR의 "🔌 연결 목록"대로 연결(import를 원본처럼 맨 위로, MOCK 제거, 목록의 테스트 추가) → `pytest -q`·`check_contract.py {N}` 통과
5. 통합 후: 단계 통합 시나리오 수동 실행 → `pytest -q` → 원본과 해당 파일 diff 확인(`git diff --no-index ../ax_class_semiproject/<file> <file>`) — 의도적으로 뺀 부분 외 차이가 있으면 원본에 맞춰 fix 커밋
