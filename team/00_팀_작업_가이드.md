# StockMind 팀 작업 가이드

국내(KOSPI·KOSDAQ)·미국(NASDAQ) 주식의 시세·지수·환율·재무·공시를 수집해 PostgreSQL에 구조화하고, FastAPI 조회·분석 API와 바닐라 HTML/CSS/JS 화면으로 제공하는 주식 분석 대시보드입니다. 4인 팀(시니어 1 · 주니어 3)이 6단계로 나눠 만듭니다.

- 완성본(읽기 전용 참조): https://github.com/Hunseokc/ax_class_semiproject
- 역할·기능 오너: [01_역할분담.md](01_역할분담.md)
- 단계별 파일 분해표: [02_단계별_로드맵.md](02_단계별_로드맵.md)
- 단계별 시작 프롬프트: [prompts/](prompts/)

## 팀원이 처음 할 일 (최초 1회)

1. 컴퓨터에 **새 빈 폴더**를 만듭니다. 이미 다른 git 저장소 안이 아닌 곳이 좋습니다.
2. 그 폴더에서 Claude Code를 실행하고 [prompts/00_setup.md](prompts/00_setup.md)의 내용을 붙여넣습니다.
   - git·gh(GitHub CLI) 설치 확인, GitHub 로그인, clone, git 설정, push 차단 훅, 작업 브랜치 생성까지 자동으로 진행합니다.
   - 도중에 역할(A/B/C/D)과 현재 단계 번호를 묻습니다. 시니어가 알려 준 값을 입력하세요.
3. 설정이 끝나면 세션을 닫고 `ax_stockmind` 폴더로 이동해 `claude`를 **새로 실행**합니다. 그때부터 [CLAUDE.md](../CLAUDE.md)의 팀 규칙이 적용됩니다.
4. 아래처럼 입력해 내 파트의 작업을 시작합니다.
   ```
   team/prompts/stage<N>.md 의 "팀원 <X>" 절에 있는 코드 블록 프롬프트를 그대로 실행해 줘
   ```
5. Claude가 **작업 계획표**를 냅니다. 읽고 승인한 뒤 파일 하나씩 진행합니다.

Stage 1 실행 전에는 Docker Desktop이 필요합니다.

## 작업 방식

Claude Code는 파일 하나마다 아래 순서를 따릅니다.

> 설계 설명 → 내 승인 → 작성 → **돌려 보기** → 코드 해설 → 이해 확인 질문 → 테스트

- 파일을 만들면 Claude가 바로 실행해서 결과를 보여 주고, 결과의 각 줄이 무슨 뜻인지 쉬운 말로 풀어 줍니다.
- 파일 몇 개가 모인 **파트**가 끝날 때마다 "여기까지 만든 것"(전/후 비교, 실제 출력·화면, 테스트 결과)을 보여 줍니다. 마지막에 빈칸 2~3개짜리 한 문장을 보기 단어와 함께 줍니다. 빈칸만 채우면 되고, 이 문장이 나중에 PR의 핵심 로직 설명 재료가 됩니다.
- 파일마다 내는 확인 질문은 객관식이고 번호만 답하면 됩니다. 틀려도 정답과 이유를 알려 주고 넘어갑니다.
- 직접 보고 싶으면: 화면은 http://localhost:8000/, API는 http://localhost:8000/docs, 명령은 입력창에 `! 명령`. 막히면 "지금까지 만든 거 보여줘".

- 내가 직접 설명할 수 있는 코드만 PR로 올립니다.
- 담당 외 파일은 수정하지 않습니다. 필요하면 Claude가 만들어 주는 요청 메모를 해당 팀원에게 전달하세요.
- 이번 단계 범위 밖의 기능은 추가하지 않습니다.

## 브랜치와 PR

```
feat/s<단계>-<a|b|c>-<기능>  ──PR──▶  stage<단계>  ──PR──▶  main
```

- `main`, `stage1~6`에는 직접 push 할 수 없습니다. 항상 PR로만 합칩니다.
- 내 브랜치는 `main`이 아니라 `stage<N>`에서 갈라져 나옵니다.
- 커밋은 파일(또는 파일+테스트) 하나 단위로, 메시지는 `feat(scope): 한국어 요약` 형식입니다. **커밋하면 바로 push** 합니다(Claude가 해 줍니다).
- push할 때마다 Claude가 만들어 주는 📣 한 줄을 **팀 채팅에 붙여 넣습니다.** 예: `📣 [S2-B] feat/s2-b-watchlist — watchlist.sql 올림 (다음: schemas)` 다른 사람이 내 코드를 언제 받아 갈 수 있는지 알 수 있게요.
- 강제 push(`--force`)와 `.env` 커밋은 금지입니다. API 키는 각자 `.env`에만 둡니다.

### PR은 일찍 열고, 파트마다 머지하기

1. 첫 push 때 Claude가 **Draft PR**을 엽니다. 이후 push할 때마다 GitHub Actions가 테스트를 자동으로 돌립니다(PR 화면의 ✅/❌).
2. 파트(계획표의 "파트별 확인 지점")가 끝나면 Claude가 PR 본문 초안과 핵심 로직 설명용 빈칸 틀을 줍니다. **핵심 로직 설명**은 내가 직접 씁니다.
3. 조건이 맞으면 Claude가 PR을 **Ready**로 바꿉니다: 테스트 통과 + 아직 머지 안 된 남의 코드가 섞여 있지 않음.
4. 시니어가 Ready PR을 머지 순서대로 바로 머지합니다. **파트 하나 = PR 하나**라서 다른 팀원이 내 코드를 하루 단위로 받습니다.
5. 다음 파트는 같은 브랜치에서 이어서 하고, 첫 push 때 새 Draft PR이 열립니다. 수정 요청이 오면 같은 브랜치에 커밋·push 하면 PR이 갱신됩니다.

### 다른 팀원의 작업을 가져오기

머지된 코드는 `stage<N>`에서 받습니다(Claude가 작업 시작 때마다 자동으로 합니다).

```bash
git fetch origin
git merge origin/stage<N>
```

**머지 전이라도 필요하면 그 팀원의 브랜치를 직접 받습니다.** 팀 채팅의 📣 한 줄에 브랜치 이름이 있습니다. 합치기는 항상 merge라 안전합니다.

```bash
git fetch origin
git merge origin/feat/s2-c-portfolio
```

이렇게 남의 브랜치를 받은 PR은 그 팀원 PR이 머지될 때까지 Draft로 둡니다(Claude가 확인합니다). 그래야 남의 미완성 코드가 내 PR에 섞여 들어가지 않습니다.

### 문제가 생기면

Claude는 문제를 **쉬운 설명 → 가장 좋은 해결 하나 → "진행할까요?"** 로만 알립니다. "응"이라고 하면 진행합니다. 다른 팀원 파일이나 D의 계약을 바꿔야 하는 문제는 추천안이 담긴 요청 메모로 만들어 줍니다. 그대로 D에게 보내면 되고, D는 OK만 답하면 됩니다.

## 시니어(D) 운영 순서

레포에 키트(`CLAUDE.md`, `.github/`, `team/`)가 올라간 상태에서 진행합니다.

1. [prompts/stage0_senior.md](prompts/stage0_senior.md)로 Stage 0(뼈대)를 만들어 `main`에 올리고 태그 `v0.1`을 답니다.
2. `git push origin main:stage1`로 단계 브랜치를 만듭니다. 이후 단계도 `main:stage<N>` 형식입니다.
3. GitHub 설정 → Branches에서 `main`과 `stage*`에 **PR 필수 + 승인 1명 + 상태 체크 `pytest` 통과 필수** 보호 규칙을 켭니다.
4. 팀원에게 [prompts/00_setup.md](prompts/00_setup.md)와 단계 번호, 역할을 전달합니다.
5. 팀원 PR을 리뷰해 `stage<N>`에 머지합니다. 머지 방식은 **Merge commit**입니다. Squash를 쓰면 주니어의 커밋이 본인 계정으로 남지 않습니다. PR은 파트 단위로 작게 오니, CI가 통과한 Ready PR은 머지 순서대로 **당일** 머지하고 팀 채팅에 알립니다.
6. 단계가 끝나면 통합 테스트 후 `stage<N>`을 `main`에 머지하고 태그를 답니다.

| 단계 | 결과물 | 태그 |
|---|---|---|
| Stage 0 | 뼈대·개발 환경 | v0.1 |
| Stage 1 | MVP — 샘플 데이터로 리스트·상세·지수 | v1.0 |
| Stage 2 | 사용자 기능 — 관심종목·모의 포트폴리오 | v2.0 |
| Stage 3 | 실데이터 — 4개 소스 수집·4시간 갱신 | v3.0 |
| Stage 4 | 분석 — 매력도·경쟁 비교·통계 | v4.0 |
| Stage 5 | 고도화 — 메모·목표가·통계 확장 | v5.0 |
| Stage 6 | 홈 대시보드 개편·상단 검색·최종 문서 | v6.0 |
